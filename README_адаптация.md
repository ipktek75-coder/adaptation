# Агент формирования плана адаптации (`adaptation_agent.py`)

## Что делает
1. **Сканирует** папку `Сотрудники` и находит карточки с профилем должности в любом
   поддерживаемом формате (см. «Поддерживаемые форматы»); ключ `-r` включает поиск по подпапкам.
2. **Извлекает текст по формату**: текстовый слой PDF (PyMuPDF), если это скан — OCR (EasyOCR
   `ru+en`, autocontrast, ×2, контраст 1.8, sharpen; результат кэшируется в `План адаптации\_cache`);
   DOCX/ODT/XLSX/TXT/MD читаются напрямую, DOC/RTF/XLS — через Word/Excel, картинки — OCR.
3. **Проверяет перечень исключений** — Приложение А РИ (файл
   `2_РИ_Перечень работников, которым не проводится адаптация.docx`): если должность в списке,
   план НЕ формируется, в отчёт пишется JSON с `"не требуется": true`.
4. **Анализирует профиль** локальной LLM (Ollama, по умолчанию `qwen3.5-64k:latest`): Ф.И.О.,
   подразделение, должность, руководитель, наставник, менеджер программ обучения,
   блоки «4.1 Теоретические знания» и «4.2 Практические навыки»; позиции с оценкой
   **меньше 4 из 5** (или без оценки) считаются **пробелами**.
5. **Профстандарт/ЕТКС**: если в профиле мало данных о знаниях и умениях (или он не читается),
   агент ищет профстандарт/ЕТКС по должности в интернете (`ddgs` + загрузка страницы) и берёт
   требования оттуда — как требует ТЗ при отсутствии профиля.
6. **Формирует Word-план** по шаблону `2_РИ_План адаптации_шаблон.docx` в папку `План адаптации`:
   шапка (таблица 1), три блока мероприятий (таблица 2), подписи. Сроки считает код:
   общий блок — первая неделя, индивидуальный — середина, итоговое задание — последние 4 недели.

## Запуск
```powershell
cd "C:\Users\pzbayur\Desktop\Проработка Адаптация"
python adaptation_agent.py                        # все карточки из «Сотрудники»
python adaptation_agent.py "путь\к\ПД.docx"        # одна карточка (любой формат)
python adaptation_agent.py "путь\к\папке"          # все карточки из указанной папки
python adaptation_agent.py "путь\к\папке" -r       # то же, включая подпапки
python adaptation_agent.py --model qwen3.5-64k:latest          # модель Ollama
python adaptation_agent.py --host http://192.168.1.50:11434   # Ollama в локальной сети
python adaptation_agent.py --no-search            # без поиска профстандарта
python adaptation_agent.py --ocr-only             # только извлечь и показать текст
python adaptation_agent.py --no-pause             # не ждать Enter (для планировщика)
```

Модель и адрес Ollama можно задать переменными окружения: `ADAPT_MODEL`
(по умолчанию `qwen3.5-64k:latest`) и `ADAPT_OLLAMA_HOST` / `OLLAMA_HOST`
(например, `http://192.168.1.50:11434` — сервер Ollama в локальной сети).

## ПОДДЕРЖИВАЕМЫЕ ФОРМАТЫ КАРТОЧЕК

Агент читает карточки не только в PDF, но и в других форматах — формат определяется
по расширению файла, при сканировании папки находятся все поддерживаемые файлы:

| Формат | Как читается | Что нужно |
|---|---|---|
| `.pdf` | текстовый слой (PyMuPDF), если его нет — OCR | PyMuPDF, easyocr |
| `.docx` (`.docm`, `.dotx`) | python-docx: абзацы, таблицы, колонтитулы (в порядке документа) | python-docx |
| `.doc`, `.rtf` | конвертация в DOCX через Microsoft Word | Word + pywin32 (для RTF есть встроенный разбор без Word) |
| `.odt` | zip + `content.xml` | стандартная библиотека |
| `.xlsx` (`.xlsm`) | zip + XML: значения ячеек по листам | стандартная библиотека |
| `.xls` | конвертация в XLSX через Microsoft Excel | Excel + pywin32 |
| `.txt`, `.md`, `.csv` | автоопределение кодировки (UTF-8 / UTF-16 / CP1251) | — |
| `.png`, `.jpg`, `.jpeg`, `.bmp`, `.tif`, `.tiff`, `.webp` | OCR скана/фото карточки (кэш в `_cache`) | easyocr |

Временные файлы Word/Excel (`~$…`) и скрытые файлы при сканировании пропускаются.
Результат OCR по-прежнему кэшируется в `План адаптации\_cache\<имя>_ocr.json`
(для картинок — тоже), поэтому повторный запуск не тратит время на распознавание.

## ОЧЕРЕДЬ ДОКУМЕНТОВ
Если в папке несколько карточек, агент выстраивает их в **очередь** (естественный порядок
имён: 1, 2, … 10) и обрабатывает **поочерёдно, по одному документу за раз**:

```
[ОЧЕРЕДЬ] ДОКУМЕНТОВ В ОЧЕРЕДИ: 3 — обработка ПООЧЕРЁДНО, по одному документу за раз
[ОЧЕРЕДЬ]   1. 01_ПД_Иванов.pdf
[ОЧЕРЕДЬ]   2. 02_ПД_Петров.docx
[ОЧЕРЕДЬ]   3. 03_ПД_Сидоров.rtf
[ОЧЕРЕДЬ] >>> ДОКУМЕНТ 1 ИЗ 3: 01_ПД_Иванов.pdf
...
[ОЧЕРЕДЬ] <<< ДОКУМЕНТ 1 ИЗ 3 ЗАВЕРШЁН за 139.1 с; в очереди осталось: 2
```

## ИТОГ И ЗАВЕРШЕНИЕ РАБОТЫ
По завершении очереди в терминал выводится счётчик обработанных документов, а окно
закрывается только после нажатия **Enter**:

```
======================================================================
ОБРАБОТАНО ДОКУМЕНТОВ: 3 из 3
  планов сформировано:                1
  не требуется (перечень исключений): 2
  с ошибками:                         0
  папка с планами: C:\...\План адаптации
  лог:             C:\...\План адаптации\adaptation_agent.log
======================================================================

Нажмите Enter для выхода...
```

Флаг `--no-pause` отключает ожидание Enter (для запуска по расписанию/в скрипте).


## Результаты
* `План адаптации\План_адаптации_<ФИО>.docx` — готовый план;
* `План адаптации\_cache\<карточка>_plan.json` — JSON по сотруднику (поля, пробелы,
  блоки, `_не_заполнено` — список полей без данных);
* `План адаптации\adaptation_agent.log` — полный лог (пишется по ходу работы).

## УЧАСТНИКИ (всегда «Должность — Фамилия И.О.»)
В колонке «Участники» агент гарантированно выводит **должность и фамилию с инициалами**
в формате «Должность — Фамилия И.О.» (несколько участников — через «; »):

| Роль | Что попадает в план |
|---|---|
| Адаптируемый работник | `<должность из профиля> — <Фамилия И.О.>` (в КАЖДОМ мероприятии) |
| Руководитель | `Руководитель структурного подразделения — <Фамилия И.О.>` |
| Менеджер программ обучения | `Менеджер программ обучения — <Фамилия И.О.>` |
| Наставник | `Наставник — <Фамилия И.О.>` либо `Наставник (не назначен)` |
| Охрана труда / коллектив | `Специалист по охране труда` / `Коллектив подразделения — <подразделение>` |

Ф.И.О. сокращает **код** (`short_fio`): «Шварева Юлия Сергеевна» → «Шварева Ю.С.»,
«Галаган Ирина Григорьевна» → «Галаган И.Г.». Приведение участников выполняет
`normalize_participants`, а не модель: LLM может написать «Руководитель», «HR»,
полное Ф.И.О. или оставить поле пустым — всё это нормализуется, дубли удаляются,
Ф.И.О. подставляются только из полей профиля (работник, руководитель, менеджер
программ обучения, наставник). В логе пишется: `участники приведены к виду
«Должность — Фамилия И.О.»: скорректировано мероприятий N`.

## ОБЯЗАТЕЛЬНОЕ ЗАПОЛНЕНИЕ ПОЛЕЙ ПЛАНА
Все поля плана заполняются обязательно, **кроме столбца «Подпись адаптируемого
работника»** — он всегда остаётся пустым (работник подписывает от руки).

Если данные по какому-либо полю получить не удалось (пусто, «Ф. И. О.» и т. п.),
в это поле выводится **красным шрифтом**: «не удалось получить данные». Правило
действует и для шапки, и для мероприятий (наименование, участники, даты, результат
проверки знаний), и для строк подписей/утверждения. Проверку выполняет `audit_plan`;
перечень незаполненных полей пишется в лог (тег `КОНТРОЛЬ`) и в JSON результата
(`_не_заполнено`).

**Шапка (таблица 1):** полное «Фамилия Имя Отчество» — только в строке
«Ф. И. О. адаптируемого работника»; руководитель структурного подразделения,
менеджер программ обучения и наставник — в формате «Фамилия И.О.».

**Подписи под таблицами** оформляются по образцу `Образец.docx`: строка вида
`<Должность>  _______________  Фамилия И.О.  <дата>`, под линией — слово
«Подпись» (10 пт), **по центру линии**. Колонки (линия для подписи, фамилия, дата)
выравниваются явными таб-стопами 7,54 / 9,55 / 11,56 / 14,74 см (плюс центральный
стоп для слова «Подпись»), поэтому во всех строках они стоят на одной горизонтали.
Пояснения «(для руководителей, принятых в дирекцию)» и «(для остальных работников
организации)» (9 пт) печатаются **на той же строке, что и слово «Подпись»**, слева —
на уровне надписи должности; «Подпись» при этом остаётся на месте. После блока
«Генеральный директор» остаётся пустая строка.

**Линия подписи** «_______________» гарантированно присутствует в каждой строке
подписей — в том числе в строке «Наставник (при назначении)», когда наставник
не назначен (значение «нет»). За это отвечает функция `ensure_sign_line()`.

Линия выводится **отдельным раном** (Times New Roman 11 пт, явный чёрный цвет):
в исходном шаблоне у части строк цвет не задан («авто»), из-за чего в отдельных
темах/просмотрщиках Word линия могла не отображаться — теперь цвет задан явно
для всех элементов нижней части (`font_color()`).

**Шрифт:** Times New Roman 11 пт — в шапке (таблица 1) и в таблице мероприятий
(кроме строки с названиями столбцов); в нижней части под таблицами размеры 12 пт
заменены на 11 пт (9 и 10 пт сохраняются).

Постоянные подписанты (подставляются во все планы):

| Роль | Значение | Как переопределить |
|---|---|---|
| Менеджер программ обучения | Смирнова Светлана Андреевна (в подписях — Смирнова С.А.) | `ADAPT_PROGRAM_MANAGER` / поле `менеджер_программ_обучения` |
| Генеральный директор | Зубарев Ю.П. | `ADAPT_GENERAL_DIRECTOR` / поле `генеральный_директор` |
| Руководитель УДЦ | Баталова Т.В. | `ADAPT_UDC_HEAD` / поле `руководитель_удц` |

## РУКОПИСНЫЕ КАРТОЧКИ (важно)
Профили должности заполняются от руки — OCR распознаёт только печатные подписи полей,
значения (Ф.И.О., должность, оценки) не читаются. Для таких карточек положите рядом
**JSON-профиль** — агент подхватит его автоматически и поля из него имеют приоритет над OCR:

```
План адаптации\_profiles\<имя карточки>.json      (например: 3_ПД Шварева Ю.С..json)
```
Пример:
```json
{
  "фио": "Шварева Юлия Сергеевна",
  "подразделение": "Отдел технического контроля",
  "должность": "Инженер по качеству 1 категории",
  "руководитель": "Галаган Ирина Григорьевна",
  "наставник": "нет",
  "менеджер_программ_обучения": "Смирнова Светлана Андреевна",
  "срок_адаптации": "с 08.09.2026 по 07.12.2026"
}
```
Если JSON-профиля нет, агент всё равно сформирует план: должность определит по OCR/названию
файла, а требования возьмёт из профстандарта — но поля шапки потребуют ручной правки.

## Зависимости
`python-docx`, `PyMuPDF`, `easyocr` (torch), `ollama`, `ddgs`, `requests`, `pillow`, `numpy`.
Tesseract в этом окружении НЕ установлен — OCR сделан на EasyOCR.
Для `.doc`/`.rtf` и `.xls` дополнительно нужны Microsoft Word/Excel и `pywin32`
(без них эти форматы не читаются; `.rtf` — только встроенным резервным разбором).
